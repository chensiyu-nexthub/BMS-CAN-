# 接下来执行路线

## 1. 总原则

用户不是只要代码，而是要能理解底层实现。所以Claude接手时应遵守：

- 每一步先解释目的，再让用户操作
- 每一步都要有可验证结果
- 不要一次性塞太多任务
- 不要跳过硬件检查直接写复杂功能
- 不要把Bootloader/F407分支混进当前BMS项目

## 2. 当前优先级

当前不要急着做APP、蓝牙、屏幕。

最优先目标：让STM32成功读到BQ76940寄存器。

原因：

- BQ读不通，后面的电压、电流、温度、保护、上位机、蓝牙、屏幕全部没有真实数据
- 当前串口已有输出，说明MCU侧已经活了
- `SYS_STAT read fail` 是当前最关键故障点

## 3. 第一阶段：硬件最小验证

需要用户确认：

- BMS板是否通过正确电源供电，而不是只靠DAPLink
- P6电池采样线是否接上真实电池组
- 电池组总压是否正常
- BQ76940相关电源是否有电
- 是否需要唤醒脚或按键唤醒
- SWD和串口是否共地

注意：真实电池有风险，所有接线必须按原理图和商家线序确认，不能凭感觉接。

## 4. 第二阶段：BQ通信打通

目标：先只读一个最简单寄存器。

建议顺序：

1. 确认软件I2C引脚和原理图一致
2. 确认SCL/SDA是开漏输出，上拉有效
3. 确认BQ I2C地址
4. 写一个最小读寄存器测试函数
5. 串口打印ACK/NAK和寄存器值
6. 先读 `SYS_STAT`
7. 再读ADC gain/offset
8. 再读VC1~VC15

## 5. 第三阶段：基础采样

当寄存器能读通后，再做：

- 单节电压原始值读取
- 电压换算公式
- 总压计算
- 温度读取
- 电流读取
- SOC简单估算

注意：BQ76940是AFE，不是电量计。SOC如果做，只能先用电压百分比或简单估算，不要说成高精度算法。

## 6. 第四阶段：保护与均衡

基础采样稳定后再做：

- 过压保护
- 欠压保护
- 过流/短路保护
- 过温保护
- 均衡开关控制

每个保护都要能讲清楚：

- 触发条件
- 恢复条件
- 控制哪个MOS或BQ寄存器
- 软件保护和硬件保护区别

## 7. 第五阶段：通信显示

最后再接：

- TTL上位机
- HC-08蓝牙模块
- 淘晶驰串口屏

通信数据来源应该统一来自BMS数据结构，不要每个显示模块各自重新读BQ。

推荐结构：

```text
BQ76940采样层 -> BMS数据处理层 -> 保护/均衡层 -> 通信显示层
```

## 8. 毕设/答辩表达重点

答辩时建议表达为：

- 本设计基于STM32F103和BQ76940实现多串锂电池组监测与保护
- STM32通过I2C读取BQ76940采集到的电压、电流、温度数据
- 软件根据阈值判断过压、欠压、过流、过温等状态
- 系统通过TTL/CAN/蓝牙/串口屏实现数据交互与状态显示
- 移动端/屏幕只是监测显示层，不直接参与底层保护闭环
