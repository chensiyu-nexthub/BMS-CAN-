# BMS项目3分钟口述稿-使用文档

## 1. 这份文档是干什么的

《BMS项目3分钟口述稿》不是方案正文，也不是源码精讲稿，而是给你在面试、自我介绍、项目汇报时直接开口用的讲稿。

它解决的是两个问题：

1. 你知道项目内容，但一张口就乱。
2. 你知道很多资料，但讲的时候容易把“实际做过”和“资料里看到过”混在一起。

---

## 2. 最推荐的使用方式

不要一上来逐字硬背，建议按下面顺序用：

1. 先把 3 分钟标准版读顺，理解每一段在回答什么问题。
2. 再把每段压成你自己的关键词，比如“项目定义、为什么做、BQ76940 定位、主链路、代码主线、SOC、保护均衡、边界声明”。
3. 然后尝试脱稿复述，不要求一字不差，但逻辑顺序不能乱。
4. 最后再练 90 秒压缩版，适应“面试官只给很短时间”的场景。

---

## 3. 每一段分别在干什么

你读稿时要知道每段的任务，不然还是会变成机械背诵。

1. 第一段是在定义项目，先把主线钉死。
2. 第二段是在说为什么做，体现你的成长动机，而不是只说“老师让我做”。
3. 第三段是在讲为什么选 `BQ76940`，同时防止把它说成电量计。
4. 第四段是在串系统主链路，让面试官知道你不是只会背模块名。
5. 第五段是在讲当前代码真实实现，告诉对方你到底能对着代码讲到什么程度。
6. 第六段是在讲 SOC 的正确理解，避免被“为什么不能只看电压”一问打穿。
7. 第七段是在讲保护和均衡的工程理解，体现优先级和约束意识。
8. 最后一段是在主动划边界，防止你把扩展方案说成现实现状。

---

## 4. 你最容易犯的错误

你现在最大的问题，不是不会背，而是容易越界。

最危险的四种错法是：

1. 把 `BQ76940` 说成“负责高精度 SOC 计算”。
2. 把 `BQ34Z100-G1`、`bq76200`、`CAN`、蓝牙说成“我这版代码已经做了”。
3. 把 SOC 说成“看电压直接算百分比”。
4. 把均衡说成“有压差就打开”。

只要你犯这四种错误之一，面试官一追问，你的项目可信度就会明显下降。

---

## 5. 在你当前思考框架之外，我给你的建议

你现在不要把这份稿子当成“背稿工具”，而要把它当成“口径约束工具”。

更直接地说：

1. 这份稿子的价值，不是让你背得像播音员。
2. 它的价值是强迫你每次开口都先分清“实际实现”“资料理解”“扩展方向”。
3. 只要这三层分得清，你后面无论是面试、答辩还是写简历，稳定性都会高很多。

---

## 6. 什么时候用 3 分钟版，什么时候用 90 秒版

用 3 分钟版的场景：

1. 面试官让你完整介绍项目。
2. 你给带你的人汇报项目理解。
3. 你做答辩开场陈述。

用 90 秒版的场景：

1. 自我介绍里顺带带项目。
2. 面试官时间短，只想先听一个总览。
3. 你回答“简单介绍一下你这个项目”的时候。

---

## 7. 用完这份稿子后应该接什么

这份口述稿不能单独使用到底，它后面一定要接源码和问答。

最合理的衔接顺序是：

1. 先练《BMS项目3分钟口述稿.md》。
2. 再看《BMS项目总复盘总稿.md》，把口述稿背后的大逻辑补牢。
3. 再进源码主线，按 `main.c -> bq76940.c -> bms_soc.c -> usart.c` 去做逐段理解。
4. 最后再练问答版文档，专门处理追问。

---

## 8. 你回来之后怎么接着用

如果你中间断了一段时间，回来不要重新乱翻资料，直接这样接：

1. 先读一遍《BMS项目3分钟口述稿.md》。
2. 试着不用看稿，口头复述一次。
3. 卡住的地方去《BMS项目总复盘总稿.md》找原因。
4. 然后再回源码定位这个点。

这样你是在“讲稿 -> 总稿 -> 源码”这个顺序里补漏洞，而不是重新掉回“资料越看越多，但越讲越乱”的状态。
